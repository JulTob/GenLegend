# TOP Reviews

Every Monday at 09:00 (Madrid), a fresh session reviews GenLegend file by file for Tag-Oriented Programming. It looks for the one redesign that would help most and moves the code toward TOP's modular idea: each resulting module **explains itself** and **stands on its own**.

Julio's permissions (2026-09-24):

- The review **may save its report here**, one file per week.
- The review **may open an issue quest** that links the report.
- **An issue does not mean the work will be done.** It is a proposal (Decree 0007). Julio decides.
- **A quest must list the questions** that need answers before the task can be finished.
- Anything else, such as changing code, pushing a branch or opening a pull request, still needs Julio's explicit permission.

## File name

`YYYY-MM-DD-short-slug.md`, dated the Monday of the review. Example: `2026-09-28-weapon-mastery-one-tag.md`.

## What a report holds

1. **Files read.** Which files were reviewed this week, and why those.
2. **The finding.** The most impactful TOP redesign: what is written today, in how many places, and what it would be as Tags. Quote file and line.
3. **Evidence.** Counts, a small probe, or the gate that would prove the change safe (fingerprint, wide sweep, replay, kit self-tests).
4. **The plan, as small points.** Each point is one commit a reviewer can check on its own, in order.
5. **Questions.** Everything Julio must decide before the plan can run, numbered so an answer can say "1: yes, 2: no".
6. **The issue quest.** A link to the issue opened for it, or why none was opened.

## 🔍 Diagnosis (what & where)

With the pin on TopKit 0.2.0a3 (QST-0093.5), Julio asked (2026-09-24) which TopKit features and patterns would benefit GenLegend, and ruled on how to apply them.

### What TopKit offers that GenLegend does not use yet

| TopKit feature | Replaces in GenLegend | Benefit |
|---|---|---|
| `Tags`, `Form`, `Outline` | nothing yet | The Decree 0009 walk, `Find_Build( char )` |
| `@Flag` | string checks and `char_class` comparisons | `"Wizard" in char`; done for Roles, Guilds, Genders, Kinships |
| `@Pin` (a Tag about Tags) | hand-kept registries (`_GUILD_DECLARATIONS`, `_CRAFT_DECLARATIONS`, `_MASTERY_TAGS`) | Catalogues that cannot drift: `for guild in Playable` |
| `@Report` builders receiving the Base's value | prefixed copies (`adrenaline_rush_uses`) and repeated per-Guild numbers | A Shape refines its Base's number |
| `@Action @Underlay` chains | AC "best of" logic; `Describe_Layer` already uses it | One rule, extended by each layer, in order |
| Named failures (`except Precondition.Aasimar_Only`) | message parsing in Minion reports and `Accept()` | Error control by name |
| `Tag[:]`, `~Tag`, `bool(char)` | nothing | Find Characters left defective, now that a failed Imprint no longer rolls back |
| `f"{char:outline}"`, `f"{char:contract}"` | Minion dumps | A readable picture of a Character |
| *0.2.0a4 (unreleased):* Field algebra `Wizard \| Fighter`, `Guild - Caster` | choice pools built by hand | Pools in one line |
| *0.2.0a4 (unreleased):* condition members `char.Has_Book` | — | A gate readable as a plain boolean |

### Two a3 behaviours every author must know

- **`bool( Tag )` asks "does this Tag have members yet?"** Never write `tag or default`, or `if tag:`, to mean "was a Tag given". Write `is not None`. Two sites did (fixed in QST-0093.5): a requested Heritage was silently replaced by a random one.
- **A Base's Preconditions do not gate a second Shape**, and a failed Imprint leaves its Tag. So a "one of a kind" rule is a gate on each Shape (below). Upstream proposal: QST-0093.10 §3.

## ✅ Julio's rulings (2026-09-24)

1. **One of a kind: a gate on each Shape, now.** Each Shape of an exclusive family declares one line, `@Pre def Only_One_X( target ): return No_X_Yet( target )`, and `No_X_Yet` is `target not in <family Base>`. Done for Species (17 Shapes), Heritage (10), Giant Heritage (6) and Celestial Revelation (3). When TopKit supports a Base-level rule, the lines collapse into one on the Base.
2. **Repeated patterns become one Tag family: a Base plus one Shape per source.** First case: **Unarmored Defense**. It is written in six places today: Barbarian and Monk training, the Bard's Dance (`_dazzling_armour_class`), legacy `Grimoire_of_Features` and legacy Monk training, and the gear rule for when armour voids it.
   - The Base, `Unarmored_Defense`, holds the formula (10 + DEX + `ABILITY`) and the armour and shield rule.
   - The Shapes declare only what differs: Barbarian (`CON`, shield allowed), Monk (`WIS`), Dance (`CHA`).
   - It is one of a kind (2024 multiclassing: a second Unarmored Defense is not gained), so each Shape carries the gate from ruling 1.
   - Draconic Resilience is its own Tag reusing the same formula helper. When several AC formulas apply, the Character uses the best.
   - Other candidates by the same measure: Extra Attack (7 Guilds), Weapon Mastery (5), Fighting Styles (3), Expertise (3).
3. **A file per Tag, for hand-written Tags.** Each Tag written as a class gets its own file, never split further; a family's shared helpers sit in its `base.py` (the pattern of `SpeciesKit/Aasimar/Revelations/`). Tags made from data by a `Make_` factory (Training, Backgrounds, Crafts, Specializations) stay as rows of their family's table file.
4. **Track TopKit releases.** Pin PyPI releases only: 0.2.0a3 now, 0.2.0a4 when published (for Field algebra and condition members).

## 🎯 Desired outcome

- Unarmored Defense as one family in `AtlasLusoris/Features/Unarmored_Defense/` (base plus one file per Shape), the six old places deleted, and the fingerprint identical except where a declared rules fix changes AC.
- The registries replaced by `@Pin` catalogues, one per commit.
- `Build_*` factories renamed `Make_*` (Decree 0009 §9).

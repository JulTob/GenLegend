## 🔍 Diagnosis (what & where)

The project runs TagKit 0.2.0a1 at upstream commit `54d50dd` (2026-08-05, the first commit of branch `codex/tagkit-0.2-alpha`); until 2026-09-07 `requirements.txt` named `c7bd376` (0.1.0), and a fresh install could not boot (found by the QST-0093.8 fresh-venv proof). Upstream `main` is 0.2.0a2 (`7aa839a`) and PR #4 adds Pins back as 0.2.0a3. Everything the project must change to run on a3 is bump-coupled: the new spellings do not exist on a1, so they cannot land early, and the old ones do not exist on a3, so they cannot stay. One branch, one gate.

## 🧾 Progress (2026-09-24, branch `julio_cl/topkit-upgrade`)

- **Renamed:** upstream is now **TopKit** (`topkit` on PyPI, module `TopKit`). `requirements.txt` pins `topkit==0.2.0a3`, a real release instead of a git commit. 68 files import `TopKit`.
- **Done:** `Has` → `in`; `Report(value)` → `Report_Of(value)` (about 70 sites; see QST-0093.10 §2); `T.Rip(a)` → `del T[a]`; `@Pin` on `Declared_Species`, `Background_Audience` and `Casting_Variant`; Species Record inputs keyword-only; `leaf.Form()` → `Form(leaf)`; named failures (`isinstance(error, TagPreconditionError)`).
- **Flags:** a3 answers `"Wizard" in char` only for `@Flag` Tags, by exact class name. The flagged Tags are Role, Player, NonPlayer, every Guild (in `Build_Guild`), the Guild, Gender and Kinship roots, Male, Female, Agender, and the seven Kinship Tags. Flagging only the roots, as the table above assumed, is not enough: a Flag answers only to its own name.
- **Found and fixed:** `instantiate()` skipped TagKit's hidden state by its old name `_TAGKIT_STATE`. Under TopKit (`_TOPKIT_STATE`) every copied item shared its prototype's Tags, so one Character un-equipping an item un-equipped another's. It showed as AC drift on 78 of 273 fingerprinted Characters.
- **Gates:** fingerprint of 273 Characters (every Guild; levels 1, 3, 5, 9, 13, 17, 20; seeds 1-3; `PYTHONHASHSEED=0`) is **identical** to the 0.2.0a1 baseline. Smoke, replay and sweep (78/78, 16 s against 24 s) pass on a fresh install from `requirements.txt`.
- **One of a kind:** the Species, Heritage, Giant Heritage and Celestial Revelation families refused a second member by raising inside an Imprint, which a3 no longer rolls back. Following Julio's ruling (QST-0093.11), each Shape now declares a one-line gate, `No_X_Yet`.
- **`bool( Tag )` trap:** in a3, `bool( Tag )` asks whether a Tag has members yet. `Apply_Species` used `requested_heritage or …`, which silently replaced a requested Heritage with a random one. A Specialization's Training features lost their "(Path)" source label the same way. Both now use `is not None`. A tracer over `bool( Tag )`, run across the wide sweep and every kit self-test, found no other site.
- **Pre-existing failures:** five self-tests already failed on `main` (FighterKit, BackgroundKit, FeaturesKit, InvocationKit, SpellsKit) and still fail at the same place. SpellsKit's `"wizard" in bolt` string check was already false on a1; on a3 it raises, because no Spell Tag is a Flag yet (the Spells port under Decree 0009 settles it).
- **Gates after the fixes:** 14 kit self-tests pass, and the wide sweep passes 1164/1164.

## How a purpose is derived today

Character.Pick(ledger, weights=None, *, purpose=None, dice=None) (AtlasActorLudi/CharactersKit.py L312-357) draws from `dice` when given; otherwise from `char.Pick_Bag(purpose)`. Pick_Bag(purpose=None, *, version="1", namespace="GenLegend") (L265-311): if purpose is None it takes `frame = sys._getframe(2)` (frame 0 = Pick_Bag, frame 1 = Pick, frame 2 = the function that called char.Pick) and builds `purpose = f"{frame.f_globals.get('__name__', '?')}.{frame.f_code.co_qualname}"` (co_qualname, so a method reads Class.method and a nested def reads outer.<locals>.inner). It then reads `drawn = char._pick_draws.get(purpose, 0)` (a per-Character dict created on first use and never reset by ~char), stores drawn+1, and returns `char.Dice_Bag(f"{purpose}#{drawn}", version=version, namespace=namespace)`. So a bare Pick in AtlasLusoris.BackgroundKit._grant_ability_boosts opens "AtlasLusoris.BackgroundKit._grant_ability_boosts#0", then "#1" on the next bare Pick from that same function on the same Character. A Pick that passes purpose= but no dice= also goes through Pick_Bag, so BackgroundKit's purpose="background.tool" opens "background.tool#0" in the default namespace "GenLegend", version "1". Character.Accept (L358-477) with in_order=False calls char.Pick(remaining, weights, purpose=purpose, dice=dice) itself, so for a bare Accept frame 2 is Accept and the derived purpose is always "AtlasActorLudi.CharactersKit.Character.Accept" whatever Tag or rite called it (verified by the derived reader's probe); with in_order=True Accept never calls Pick and opens no bag. Dice_Bag(purpose, *, version="1", namespace="GenLegend") (L479-527): strips purpose/version/namespace, raises ValueError on an empty purpose or namespace, builds `material = f"{char.seed}|{purpose}|{version}".encode("utf-8")`, `digest = blake2b(material, digest_size=16, person=namespace.encode("utf-8")[:16]).digest()` and returns `random.Random(int.from_bytes(digest, "big"))`. Consequences: two sites with the same (purpose, version, namespace) get identical fresh streams; renaming a purpose or changing version/namespace changes every value the bag yields; a derived purpose that several Tags share (one helper function) makes the stream for one Tag depend on how many times the others drew first. FeaturesKit._Plan_Training (L773) composes its own bag as f"{purpose}.{resolved_id}" (version "2024", namespace "GenLegendTraining") where resolved_id = grant_id or _Next_Grant_Id(char, feature), so purpose="guild.Monk.tool" with grant_id="Guild.Monk.tool" opens "guild.Monk.tool.Guild.Monk.tool".

## Purposes that belong to no Tag (they keep their names)

- identity.alignment (AtlasActorLudi/AlignmentKit.py L219): the Player's alignment is Character identity; the Alignment Tags are the outcome, none of them offers the choice.
- identity.species (AtlasActorLudi/SpeciesKit/application.py L17): choosing the Species itself precedes any Species Tag.
- identity.gender (AtlasActorLudi/GendersKit.py L166): Gender Shapes are the outcome, not the offerer.
- identity.guild (AtlasLusoris/Grimoire_of_Guilds.py L3084): the Guild family draw precedes any Guild Tag.
- identity.background (AtlasLusoris/BackgroundKit.py L2620): the Background family draw precedes any Background Tag.
- identity.scores (AtlasLusoris/Grimoire_of_Characters.py L682): the ability-score roll belongs to the Character skeleton (Player), not to a Tag.
- identity.story (AtlasEpica/Map_of_Stories.py L63): the story engine owns the Monomyth collapse; no Tag offers it.
- Epica.Title and Epica.Title.LastResort (AtlasEpica/Map_of_Titles.py L110/L27): the title vocabulary is the Epica engine's, used by both New_title and the story heading.
- Nomina.LastResort (AtlasNomina/Map_of_Names.py L163): naming fallback of the Nomina engine.
- identity.name.* (AtlasNomina Map_of_Names L569/L279/L289/L294/L299/L335/L276/L704, Map_of_Markov L33, Map_of_Word_Entropy L124, AtlasLudus/Map_of_Useful_Functions L10): the naming engine composes words from Species ingredients but no Tag offers the name; these keep an identity.name prefix while moving off the global stdlib generator.

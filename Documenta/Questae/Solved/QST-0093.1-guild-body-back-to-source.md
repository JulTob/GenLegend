## 🔍 Diagnosis (what & where)

`AtlasLusoris/Grimoire_of_Guilds.py` is a `marshal.loads` shim over `.recovery-vault/GuildKit.cpython-314.pyc`. Every Player build executes it. Its bytecode was compiled against the old TagKit API (`Report(value)`), so it cannot be migrated; and it cannot be read.

The authentic source survives in history: commit `65edc0f` ("GuildKit returns as its authentic pre-wipe source"), 2,997 lines, no `marshal`. Compared name for name with the live bytecode module's `__all__` on 2026-09-06: all 100 public names present, nothing missing. It carries one `Report(value)` site (line 1632) and one `Has`.

## 🧾 Evidence

- `git show 65edc0f:AtlasLusoris/GuildKit.py | wc -l` → 2997; AST top-level names ⊇ live `__all__` (100 of 100).
- Live shim header: "keeps the surviving Aug 28 bytecode for Build_Guild and its helpers until those protocols are rewritten as source".
- The shim defers `Load_Guild_Libraries` while the bytecode executes; the source version calls it at line 2 of its own accord.

## 🎯 Desired outcome

`Grimoire_of_Guilds.py` is the 65edc0f source (with the spec/body split kept: `GuildKit.py` stays the re-exporting spec). Seed 42 is still Nikolas Amexafa; the 78-cell and wide sweeps are unchanged; the replay is exact. The shim, and the Player path's dependency on the vault, are gone.

## 🧭 Notes for the Agora / implementer

- Keep the deferred `Load_Guild_Libraries` ordering the shim documents; the kits import GuildKit, so the spec must finish re-exporting before the libraries load.
- Do not migrate the `Report(value)` site here; that is station 5. This station changes nothing observable.
- The static bytecode gate (marshal the restored source, compare code objects) is the honest proof that the restore is the same program.

## ✅ Resolution
- **Decided by:** Julio, 2026-09-18 ("can we update the GitHub Guilds to be
  properly maintainable?").
- **What changed:** `65edc0f`'s 2,997-line source is now the body of
  `Grimoire_of_Guilds.py`, and the `marshal` shim is gone. Three edits on top
  of the verbatim source, two of them deliberately line-neutral so the proof
  below stays exact:
  1. the header names the file and points at its spec;
  2. the mid-file `Load_Guild_Libraries()` call (line 2181) became the comment
     that says why the spec makes that call instead, which is what the shim
     was doing at runtime by neutering the name during `exec`;
  3. the computed `__all__` moved from the shim into the body, with the
     shim's `_SKIP` set minus its own loader artefacts (`marshal`, `Path`).
  `GuildKit.py` is untouched but for a docstring paragraph on the ordering.
- **Proof:** the static bytecode gate, run against
  `.recovery-vault/GuildKit.cpython-314.pyc`: of 106 code objects, 105 are
  byte-identical, the 106th being `<module>` itself (the docstring line, the
  removed call, the added `__all__`), plus one new `<genexpr>` for the
  `__all__` comprehension. Every function and every class the app runs is the
  same program. `GuildKit.__all__` is the same 100 names; the only globals
  that disappeared are the shim's own (`marshal`, `Path`, `_PYC`, `_SKIP`,
  `_guild_libraries`, `_load_guild_libraries`). Seed 42 is still Nikolas
  Amexafa, the replay is exact, the Aasimar page is clear, the 78-cell sweep
  is 78/78, and the wide sweep is 1,164/1,164 with zero failures.
- **Practice/preference to remember:** `__firstlineno__` makes a class body's
  bytecode depend on where the class sits in the file, and below line 255 it
  changes the instruction too (`LOAD_SMALL_INT` no longer fits). So an edit
  *above* a class silently fails a code-object comparison that is otherwise
  exact. Keep the edits above the last class line-neutral and the gate reads
  clean, instead of reporting six differences you then have to argue away.

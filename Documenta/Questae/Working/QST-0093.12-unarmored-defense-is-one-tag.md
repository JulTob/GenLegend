## 🔍 Diagnosis (what & where)

Three Guild features share one rule. With no armour on, the base Armor Class is 10 + Dexterity modifier + one more ability modifier. Only two facts change from source to source:

| Source | Ability | Shield allowed? |
|---|---|---|
| Barbarian | CON | yes |
| Monk | WIS | no |
| Bard, College of Dance (Dazzling Footwork) | CHA | no |

Before this questa the rule lived in six places:

1. three hidden "skill" markers (`Unarmed_Barb`, `Unarmed_Monk`, `Unarmed_Dance`) set in `Grimoire_of_Characters.set_Skills`;
2. `Map_of_Gear_Proficiency`, which read those markers to compute the AC and to decide whether a shield or armour voids it;
3. a private copy of the formula in each of the Barbarian, Monk and Bard Training maps (for the entry text and the Chip);
4. the Bard's `_apply_dazzling_footwork`, which also wrote `char.AC` directly, a stored number that the derived AC overwrote a moment later.

Julio (2026-09-24): *"make the unarmored Defense family, which could probably be just one tag that marks the stat to use as extra defense."*

## 🛠️ What landed (commit `6e2cc6a`)

- `AtlasLusoris/AtlasOfFeatures/Unarmored_Defense.py`: one Tag, one file.
  - `Unarmored_Defense( char, ability="CON", shield_allowed=True )`. Two gates refuse an unknown ability or a missing shield rule. Two Records keep the inputs on the Character.
  - Readers: `Unarmored_Ability`, `Shield_Voids_Unarmored_Defense`, `Unarmored_Armour_Class`. Nobody else computes the formula. "Does the Character have it?" is TopKit's own question: `char in Unarmored_Defense` (Julio: no wrapper).
  - `CHIPS`: one `AtlasVenustas.Chip( "🛡️", "Unarmored AC", Unarmored_Armour_Class )`. It is the first Tag the build walk reads (QST-0093.14).
  - Applying it again does nothing (TopKit), so the first source wins.
- `Map_of_Gear_Proficiency`: `has_unarmoured_defence`, `armour_voids_unarmoured` and `unarmoured_formula` now ask the Tag. The private formula and the marker-reading helper are gone.
- `Grimoire_of_Characters.set_Skills`: applies the Tag where it used to set the three markers.
- Barbarian, Monk and Bard Training: their entries and Chips read `Unarmored_Armour_Class`. Their private formulas and the Bard's `char.AC` write are gone.

## 🛡️ Gear policy (Julio, 2026-09-24)

*"A character with unarmored should not get armors as equipment. I know technically it allows, but the fantasy is kind of broken, then, and the player can always go and get one when playing. At presentation, it makes more sense to block armors."* And: a source that allows a Shield gets one; a source that does not, doesn't.

- `Map_of_Gear_Proficiency.unarmoured_refuses_armour( char )`: true for every Character with the Tag. `GearKit._fit_armour` hands them no armour, whatever their armour training.
- `Map_of_Gear_Proficiency.unarmoured_refuses_shield( char )`: true when the source does not allow a Shield. `may_use_shield` asks it.
- `GearKit`'s own check and `scripts/verify_equipment.py` fail a Character that breaks either rule.
- This replaces `armour_voids_unarmoured`, which mixed the two ("a Monk gets neither; a Barbarian may get Medium armour").

**What it changed (on purpose):** 15 of the 21 Barbarians on the wide grid used to wear Medium armour (Scale Mail, Half Plate, Demi-Plate). They now wear none and keep their Shield. Their gold goes elsewhere (tools, a better Shield, a wonder), so AC moved: 13 went down by 1–2, and 2 went up by 1 (level 17 and 20, seed 2, where the gold bought a better Shield and more gear). No other Guild changed.

## 🧾 Evidence

- Fingerprint, wide grid (levels 1, 3, 5, 9, 13, 17, 20; seeds 1–3): 273 of 273 identical for the Tag itself (commit `6e2cc6a`). After the gear policy: 258 identical, and the 15 Barbarians above differ in the declared way.
- Wide sweep 1164/1164. Replay exact. `verify_equipment` (seeds 20): output identical to `main`, including its 195 known `'<'` chip-label failures (QST-0141).
- No generated Character with the feature has a negative bonus ability (82 checked), so the "take the better of 10 + DEX and the formula" rule changes no number today. The old Training Chips did not take the better, the gear rule did; now both agree.

## ❓ Questions to answer before this is Solved

1. **Two sources, which wins?** Today the first applied wins, and a second source changes nothing. That matches the 2024 multiclass rule (you don't gain Unarmored Defense again). Is that what you want, or should the Character keep the best of the two?
2. **Who applies the Tag?** It is applied in `set_Skills`, because the gear is chosen *before* Guild Training awakens (`Grimoire_of_Characters`, "Gear BEFORE Guild training"), and the gear needs to know. Should Training move before gear, so each source's Training Tag applies it itself? That puts each fact next to the feature that describes it, but it reorders creation and needs its own gate run.
3. **Draconic Resilience.** The Draconic Sorcerer's entry promises "13 + Dexterity" with no armour, but no rule computes it: the AC ignores it. Should it become this same Tag with one more input (a base of 13, no extra ability)? Please check the 2024 text too. If I remember it right, the 2024 book changed it to 10 + Dexterity + Charisma, which is exactly this Tag with `ability="CHA", shield_allowed=True`.
4. **The legacy skill markers.** The Tag still marks one of the three `Unarmed_*` slots, only so the proficiency line keeps printing "Unarmed Defense". May the proficiency line read the Tag instead, so the three slots can be deleted?
5. **The legacy copies.** `Grimoire_of_Features.set_UnarmoredDefense` and `Map_of_Classes/Training/Barbarian.py` and `Monk.py` still carry their own text or formula, and the legacy progression still imports them. Delete them here, or with QST-0093.7 (the Player path off legacy)?

## 🗣️ Julio's answers (2026-09-24)

- **Question 3, Draconic Resilience:** *"Draconic Resilience doesn't exclude Unarmored Defense, so it should be an independent tag. A feature of draconic ancestry."* It is its own Tag, and the Armor Class takes the best of the formulas that apply. Which formula (13 + DEX, or 10 + DEX + CHA) is still open.

## 🎯 Desired outcome

One place states the rule; every reader asks it; the sheet's number and the real AC are always the same number.
